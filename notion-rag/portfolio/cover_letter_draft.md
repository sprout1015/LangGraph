# 자기소개서 초안

> **사용 방법**: `[회사명]` 또는 `귀사` 표기 부분만 실제 지원 회사명으로 교체하여 사용합니다.  
> 각 항목은 1,000자 이내로 작성되었습니다.

## 문항 1. 지원 동기 및 입사 후 목표

> "ㅁㅁ에 지원하게 된 동기와 입사 후 이루고 싶은 목표를 구체적으로 작성해 주세요."

저는 '보이지 않는 선택의 무게를 고민하고, 시스템의 지속 가능성을 설계한다'는 철학으로 개발해왔습니다. 기능이 동작하는 것에서 그치지 않고, 설계 단계에서 리스크와 운영 비용을 선제적으로 판단하며 서비스가 장기적으로 확장·유지될 수 있는 구조를 만드는 것이 백엔드 엔지니어의 본질이라고 생각합니다.

귀사에 지원하게 된 이유는 귀사가 추구하는 기술 방향성과 제가 쌓아온 역량이 의미 있게 맞닿는 환경이라고 판단했기 때문입니다. 저는 결제·구독·배치·인프라를 포함한 백엔드 전 영역을 혼자서 End-to-End로 설계하고 운영해온 경험이 있습니다. 단순 개발을 넘어 CI/CD 파이프라인 자동화, Prometheus·Grafana 기반 모니터링 체계 구축, 인프라 보안 최적화까지 직접 책임지며, '기술 결정 하나가 서비스 안정성과 팀 생산성 전체에 어떤 파장을 미치는지'를 실감했습니다. 이 경험을 통해 PDCA 사이클을 기반으로 기술 과제뿐 아니라 운영 효율과 팀 협업 구조까지 함께 개선하는 엔지니어가 되어야 한다는 확신을 갖게 됐습니다.

입사 후 단기적으로는 귀사 서비스의 아키텍처와 도메인 로직을 빠르게 체화하여 팀에 즉각적인 기여를 만들겠습니다. 중장기적으로는 현재 개인 프로젝트로 연구 중인 RAG 파이프라인과 로컬 LLM 파인튜닝 기술을 실제 서비스에 접목하여, 귀사의 기술 경쟁력을 함께 높이는 데 실질적으로 기여하고 싶습니다. 기술로 문제를 해결하는 것에 그치지 않고, 조직의 성장에 함께하는 엔지니어가 되겠습니다.

> **※ 약 830자**

## 문항 2. 직무 관련 지식·기술 및 활용 방안

> "지원한 직무와 관련하여 본인이 쌓아온 지식·기술을 설명하고, 이를 바탕으로 입사 후 직무 수행에 어떻게 활용할 수 있을지 구체적으로 작성해 주세요."

저는 Spring 생태계를 중심으로 백엔드 기술 역량을 쌓아왔으며, 이를 실제 운영 환경에 반복적으로 적용하며 깊이를 더해왔습니다. 핵심 역량은 네 가지 축으로 정리됩니다.

**첫째, Spring 생태계 전반에 걸친 실무 역량입니다.** Spring Boot, Batch, Security, JPA, MyBatis, R2DBC를 실무 프로젝트에서 모두 활용했으며, 단순 사용을 넘어 각 기술의 트레이드오프를 이해하고 상황에 맞게 선택해왔습니다. 특히 Spring Batch와 Quartz 스케줄러를 결합하여 외부 API 4,000건 이상의 대용량 데이터를 처리하는 배치 시스템을 직접 설계·운영했습니다.

**둘째, 인프라·배포 자동화 역량입니다.** Docker와 GitHub Actions 기반 CI/CD 파이프라인 구축으로 배포 시간을 15분에서 3분으로 단축했고, Terraform을 활용한 IaC로 인프라를 코드로 관리하는 경험을 갖추었습니다.

**셋째, 모니터링·보안 체계 구축 역량입니다.** Prometheus + Grafana + Exporter를 활용한 실시간 모니터링 대시보드를 구축하고, Redis L2 캐싱과 JWT·OAuth2 기반 인증 체계를 직접 설계·운영했습니다.

**넷째, AI/ML 실무 접목 역량입니다.** Notion API 기반 RAG 파이프라인을 End-to-End로 구축하고 FastAPI·Discord 봇을 통한 다중 인터페이스 서비스를 개인 프로젝트로 완성했으며, 로컬 LLM LoRA 파인튜닝과 Claude Code SubAgent 활용을 통한 AI 기반 개발 환경 구성 역량도 보유하고 있습니다.

입사 후에는 이러한 역량을 바탕으로 귀사 서비스의 안정성·성능 개선과 운영 효율화에 기여하겠습니다. 특히 모니터링 체계 강화, 배포 자동화, AI 기술 접목 과제에서 빠르게 가시적인 성과를 만들고 싶습니다.

> **※ 약 870자**

## 문항 3. 어려운 상황에서 책임감 있게 수행한 경험

> "어려움이 큰 상황에서도 책임감 있게 과제를 수행했던 경험을 구체적으로 작성해 주세요. 당시의 구체적인 상황과, 이를 통해 얻은 교훈을 함께 설명해 주시기 바랍니다."

실시간 선물 거래 플랫폼의 백엔드와 클라우드 인프라를 혼자서 End-to-End로 설계·개발·운영하는 역할을 맡았습니다. 서비스는 CES에 출품될 예정이었고, 50개 이상의 외부 API와 연동해야 하는 복잡한 도메인을 단독으로 책임지는 상황이었습니다.

가장 어려웠던 순간은 외부 API에서 매일 4,000건 이상의 상품 데이터를 동기화하는 배치 시스템을 구축할 때였습니다. 초기에는 단순 INSERT/UPDATE 방식으로 접근했으나, 대량 데이터로 인한 DB I/O 과부하와 중간 실패 시 데이터 정합성 문제가 발생했습니다. 일정 압박이 있는 상황에서 임시방편으로 넘어갈 수도 있었지만, 운영 환경에서 반복 실행될 배치의 신뢰성을 포기할 수 없었습니다.

Spring Batch의 Reader-Processor-Writer 패턴과 100건 단위 청크 처리, JdbcBatchItemWriter를 활용한 배치 업데이트를 적용했습니다. Quartz 스케줄러와 연동하여 AbstractQuartzBatchJob 구조를 설계하고, 모든 Job의 실행 이력과 실패 시 재시작 정책을 체계적으로 관리했습니다. 그 결과 DB I/O를 대폭 절감하고 실패 지점부터 자동 복구 가능한 안정적인 배치 시스템을 완성했으며, CI/CD 개선으로 배포 시간도 15분에서 3분으로 단축했습니다.

이 경험을 통해 일정 압박 속에서도 운영 환경을 고려한 '올바른 선택'을 관철하는 것이 장기적으로 더 큰 가치를 만든다는 것을 배웠습니다. 기술적 완결성에 대한 책임감이 서비스의 신뢰성과 팀의 생산성을 동시에 지키는 원칙이 된다는 교훈을 얻었습니다.

> **※ 약 840자**
